# Configured source generation at every default entry

This repairs the default-source bypass diagnosed in
[the protected configuration join](compiler_protected_configuration_join_5_0_6.md).
The baseline remains the exact Rust 5.0.6 locks. G13/G14/G17 remain partial.

The default generic service previously accepted both
`generateDomainFiles(GenerateContext)` and
`generateSourceFiles(Domain, GenerateContext)` without a registered compiler.
Both returned interpreted C++ files, including an entity named `option`, while
the trusted factory correctly rejected missing compiler configuration.

## Implementation

The model-layer `SourceGenerationRequirement` interface lets a generator declare
that public source calls need a trusted source callback. `CppCoreGenerator`
declares that requirement and supplies an actionable locked-compiler diagnostic.
The generic service checks matching requirements before either source overload
can fall back to domain generation. It has no C++-specific import or scope rule.

Explicitly installed source callbacks retain priority and receive the existing
cloned source snapshot. The already-parsed controller Domain cannot replace
compiler input. Callers assemble C++ services through
`CppCompilerServiceConfiguration.fromSystemProperties()` or trusted source
callbacks. The explicit domain-only maintenance API and direct emitter retain
their behavior. Java source generation retains its existing generated bytes.

The configured factory continues to apply the shared reserved-name rule before
worker invocation. An unconfigured default service rejects every C++ source
request before producing an SDK; it cannot bypass that boundary by accepting
`option` or `Option` through interpretation. Uploaded and dynamic requests using
an unconfigured generic service also fail before ZIP publication.
