# TeaQL C++ 0.1.0

The first public TeaQL C++ release provides the C++20 runtime and SQLite provider
for edge applications. The C++ release number is independent of the locked Rust
5.0.6 reference design. Earlier 0.0.x tags remain historical checkpoints.

## Downloads

Use the assets at
[GitHub Releases](https://github.com/teaql/teaql-cpp/releases/tag/0.1.0):

- `teaql_cpp_0.1.0_source.tar.gz`: compact runtime source distribution, including
  the seven packages, retained examples, module interfaces, CMake installation
  files, toolchain setup and development documentation.
- `release_verification.json`: source identities, package contents, exact commands
  and results from the independent distribution checks.
- `SHA256SUMS`: SHA-256 checksums for the source distribution and verification
  record.

The compact distribution omits the repository-wide qualification harness,
historical evidence and downloaded tools. Build it with `BUILD_TESTING=OFF` as
shown below. GitHub's automatically generated source archives and the `0.1.0`
Git tag retain the complete repository, including tests and acceptance evidence.
Generated example code is included; building or running it needs no generator.

## Included behavior

- Context-bound typed Q queries and composable E expressions, projections,
  relation loading, aggregates and list, one, page and scalar-stream execution.
- Audited graph Save, distinct mutation/snapshot/value responsibilities,
  Checker/Fix, Behavior, configured request and mutation policies, optimistic
  versions and transaction-scoped persistence.
- SQLite schema initialization, modeled bootstrap, business IDs, dynamic fields,
  typed JSON, inheritance, constants, candidates and generated model guidance.
- Explicit GlobalContext and UserContext allocation lifetimes, growing arenas,
  bounded allocation identities, checked references and registered RAII cleanup.
- Intent-aware diagnostics, sensitive-binding controls and post-commit
  application audit delivery.
- Independent memory, async, core, data-service, SQL, runtime and SQLite-provider
  packages, CMake imported targets and optional C++20 named-module interfaces.

## Build and install the source distribution

The supported native development profile is Linux x86_64 with the versions in
`toolchains.lock.json`: Clang 23.1.3, GCC/libstdc++ 16.2.0, CMake 4.4.4, Ninja
1.13.2 and SQLite 3.53.2. Setup uses Python 3, network access, tar, zstd and
system libc development headers; tools are development dependencies and are
not included in the release archive. The existing setup installs the locked
native and MIPS toolchains; this guide builds only the native header frontend.

From the directory containing all three downloaded assets:

```bash
set -e
sha256sum --check SHA256SUMS
tar -xzf teaql_cpp_0.1.0_source.tar.gz
cd teaql_cpp_0.1.0
python3 scripts/toolchains/setup.py
source scripts/toolchains/activate.sh
cmake --preset native -DBUILD_TESTING=OFF \
    -DCMAKE_INSTALL_PREFIX="$PWD/install"
cmake --build --preset native --parallel 2
./build_native_current/teaql_generated_query_expression
cmake --install build_native_current
```

The generated example uses a fresh in-memory SQLite database and prints
`generated-order: keyboard`. The build also includes the other four retained
examples. On memory-constrained build hosts, use one build job. Nothing must run
on the target router to build or consume this source package.

## Consume an installed runtime

Use the same compatible toolchain for the runtime and its consumer. A separate
application's `CMakeLists.txt` can use:

```cmake
cmake_minimum_required(VERSION 4.4)
project(my_application LANGUAGES CXX)
find_package(teaql_cpp 0.1.0 EXACT CONFIG REQUIRED)
add_executable(my_application main.cpp)
target_link_libraries(my_application PRIVATE teaql::provider_sqlite)
```

From the extracted release directory, configure that application with the
same locked compiler and native SQLite build used for the runtime:

```bash
cmake -S /path/to/application -B /path/to/application/build -G Ninja \
    -DCMAKE_TOOLCHAIN_FILE="$PWD/scripts/toolchains/clang_native.cmake" \
    -DCMAKE_PREFIX_PATH="$PWD/install" \
    -DCMAKE_BUILD_TYPE=Debug \
    -DSQLite3_INCLUDE_DIR="$PWD/.tools/toolchains/sqlite-3.53.2/include" \
    -DSQLite3_LIBRARY="$PWD/.tools/toolchains/sqlite-3.53.2/lib_native/libsqlite3.a"
cmake --build /path/to/application/build --parallel 2
```

Selecting `lib_native` explicitly chooses the host archive from a setup that
also contains a MIPS archive. Keep SQLite headers and libraries compatible with
the runtime build. Generate model-specific domain libraries separately; the
runtime release does not install the generator. The
[installed package guide](../module_packaging.md) lists all seven imported targets
and the optional modules component.

## Boundaries

SQLite is the only database provider in this release. Header consumption is the
default native profile. Named modules are qualified for the documented native
Clang/Ninja profile; interfaces are distributed as source and consumers build
matching BMIs. OpenWrt MIPS uses headers and retains its earlier cross-build/QEMU
evidence; physical-router execution remains unverified. This release does not
claim a fresh full module, sanitizer, MIPS or physical-device run.

Graph Save atomicity follows the provider/route. Modified persisted objects
need complete scalar loading. Scalar cursor streaming does not perform relation
or aggregate enhancement. Schema reconciliation adds tables and columns;
destructive schema migration is outside that contract. Audit delivery is not a
durable outbox, and an audit failure after commit does not roll back the write.
Applications configure their authorization policies. Raw pointers, references
and ordinary Q/E wrappers remain borrows and become invalid after Context close.

Approved C++ behavior differences are recorded in the acceptance report. The
runtime retains correct JSON payload and quoted-foreign-key behavior, explicitly
rejects invalid JSON naming and unsafe column-attribute configurations, and
uses the shared `option`/`Option` reserved-model-keyword policy. This is an early
C++ release; compatibility across future 0.x releases should be reviewed before
upgrading.
