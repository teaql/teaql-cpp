## Comparator repairs and controls

The [complete preceding CLI controls](parity/expression_cli_admission_original_5_0_6.json.gz)
reproduce **nine false acceptances**:

- Framing accepts an appended record or a truncated corpus retaining its control case.
- Text accepts empty list/object cases, a partial or appended corpus, and an extra native diagnostic field.
- Generated diagnostics accept partial or appended corpora.

The shared case guard requires the complete retained cardinality and exact
input/expected record fields before running an observer. Text rendering now
requires the complete nine-field native surface. Generated diagnostics use the
existing strict JSON-kind comparator and LF-framed observer helper.

The [installed admission replay](parity/expression_cli_admission_installed_5_0_6.json.gz)
passes **89/89 controls**. These controls replay actual current native outputs
to isolate the Python verification boundary; counterfeit outputs are not Rust
or C++ runtime evidence. Naming and English-message adapters remain explicit.
No timestamp, business value, query state or load-state normalization is added.

The permanent [source registry](../tests/parity/expression_cli_source_contracts_5_0_6.json)
binds all six complete corpora to their actual original drivers, generated
libraries, dependency graph, raw stdout and current adapter/probe identities.
It also pins legacy source declarations referenced by the comparison scripts.
Those declarations are not substituted for the actual compiled observer.

The [source controls](parity/expression_cli_source_controls_5_0_6.json.gz)
