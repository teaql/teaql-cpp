# Governed business execution through the compiler host

This continues the [trusted host assembly](compiler_host_assembly_5_0_6.md)
with the complete protected consumers required by E02/GP11. It preserves the
locked Rust 5.0.6 references, the [P0-P7 plan](cpp_generator_parity_plan.md) and
the separate pending E03/E04 choices. Source/compiler/runtime responsibilities
and both C++ allocation domains remain unchanged.

## Execution contract

The two existing composed primitive/tuple models enter the ordinary Spring
controller as uploaded source packages. Trusted startup configuration installs
the existing v4 compiler service. The worker generates and compiles the complete
original Rust SDK, observes descriptors, scalar storage and typed projections
from the same library artifacts, then produces the C++ SDK.

Both successful SDKs contain 96 files. The complete SDK manifest returned by
each host job equals the manifest actually compiled by its native business
observers. The original and C++ consumers use separate generated libraries and
build directories. The reference business generator retains its
`inheritance_graph.xml` entrance; the controller uses the required `main.xml`
ZIP entrance with identical XML content. Those source-package and process
adaptations are recorded explicitly, without claiming identical file-origin
annotations or one shared Rust artifact across the two routes.

All eight typed relations target Enrollment. The complete configuration retains
audit length 17. The partial configuration contains an invalid later relation
and retains length 13 and its previously accepted prefix, following the original
macro behavior. Neither the model nor the original generated Rust is repaired
locally to obtain these outcomes.
