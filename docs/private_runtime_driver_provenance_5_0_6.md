## Complete project and distinct corpus roles

The [contract registry](../tests/parity/private_runtime_driver_contracts_5_0_6.json)
covers all **34** executable targets and **39** retained corpora. The
[fresh replay](parity/private_runtime_driver_execution_5_0_6.json.gz) compares
**61,924** raw original/corpus/native observations without output normalization.
The **36 new corpora / 34,846 observations** are separate from three previously
qualified Registry corpora / 27,078 repeated observations. Repeated evidence
does not increase cumulative counts.

Responsibilities include graph Save/Fix/Policy/ledger execution, transaction
ownership and failure order, layered query intent, entity query/stream/cache/page
orchestration, relation execution, graph hydration and JSON read views. These
are the retained inputs of the existing observers; a complete project build
does not claim exhaustive coverage of every semantic input or provider.

The replay extracts all **610** files from the locked archive into an owned
temporary directory. Original bytes remain intact; the existing builder's nine
append-only access bridges retain their exact contents and imported helper
identities. Original manifests and dependency declarations are preserved. No
dependency or disabled telemetry development dependency is removed. Actual Cargo
metadata identifies the five original TeaQL dependencies and all executable
targets. The copied observer lock is resolved only in the owned project; actual
compilation uses `--offline --locked --bins`. Registry package identities and
checksums must belong to the locked reference.

Observer sources, their two shared Rust fixtures and the extraction build script
remain unchanged. Owned source links resolve to the actual retained files. Four
compiled extraction outputs are retained in full and independently reconstructed
from the locked base/context/relation/helper source ranges. The existing reduced
SPI fixtures and complete runtime calls retain their distinct responsibilities;
source extraction is not represented as a complete runtime replacement.

## Historical input transformations

The first validator attempt incorrectly required every historical corpus to
have identical inputs. The [diagnosis](parity/private_runtime_driver_historical_input_diagnosis_5_0_6.json.gz)
retains the three counterexamples. Existing explicit-intent corpora intentionally
expand the historical layered-query inputs with valid, blank and padded purposes.
The relation-intent corpus supplies recursive child query intent and six
additional membership variants.

The validator now reconstructs those exact existing transformations and checks
their source fingerprints against the original execution input snapshot. Other
historical corpora require unchanged ordered inputs. This correction changes
neither current stimuli nor expected outcomes, observer algorithms, production
C++ or generated artifacts. Fresh Rust execution is reused because all its inputs
and raw observations remain unchanged; validation has its own later epoch.

## Verification boundaries

The [validator](../scripts/verify_private_runtime_driver_contracts_5_0_6.py)
checks archive prefixes, exact bridges, fixtures, manifests, compiled targets,
local dependency paths, registry locks, extraction outputs, raw input identities
and complete ordered results without compiling Rust in routine CTest. Its
[binding receipt](parity/private_runtime_driver_bindings_5_0_6.json.gz) records
the source/corpus/native scope. All
[29 negative controls](parity/private_runtime_driver_controls_5_0_6.json.gz)
reject archive/bridge substitution, changed source links and fixtures, replaced
targets and dependencies, unlocked or partial builds, empty locks, self-rehashed
extractions, missing or duplicated results, Boolean/number confusion and changed
historical adapters. The actual invariant dispatcher command is retained
[separately](parity/private_runtime_driver_dispatcher_5_0_6.json.gz).

The [first integration receipt](parity/private_runtime_driver_gates_5_0_6.json.gz)
records 43 passing native tests but a failed harness assertion: its expected
names omitted the existing entity-runtime source fixture. The
[final gate](parity/private_runtime_driver_gates_final_5_0_6.json.gz) retains exact
JUnit names for **43/43** affected and **2/2** focused tests. It preserves both
existing Registry/entity-runtime source fixtures while adding the new fixture
to all 39 comparisons. Current native/modules configuration and no-work build
steps are reused from the first receipt after checking identical input hashes.
The affected/focused execution is fresh; configuration reuse is explicit.

901 registered tests, 305 direct corpus registrations and 181 custom-dispatcher
entries. It is not a fresh full 901-test execution. Across disjoint contracts,
source bindings cover **111 unique corpora / 142,310 observations**. Remaining
work includes **194 direct registrations** and **31 of 107 declared-driver
project/view responsibilities**, plus complete custom CLI, dependency,
normalization and protected-execution obligations.

All 1,813 C++ inputs preserve the frozen native893 identities. Producer
implementations, generated SDKs and module exports are unchanged; earlier
metadata source63,918/Java134 and artifact gates retain their separate epochs.
All [25 current source guards](parity/private_runtime_driver_guards_5_0_6.json.gz)
also retain pinned formatting and baseline/path checks. The
[cleanup report](parity/private_runtime_driver_cleanup_5_0_6.json.gz) verifies
exact owned directories were removed after terminal completion; shared caches,
stable presets and compact receipts remain. The
[milestone](parity/private_runtime_driver_milestone_5_0_6.json.gz) seals source,
status and receipt identities without promoting an incomplete capability.

No original Rust embedded unit-test execution, fresh full native suite,
imported-module execution, sanitizer, MIPS/QEMU or physical-device run is claimed
by the replay. SQLite observations use the existing in-memory fixture. Full
metadata grammar/configuration, protected execution, remaining direct/custom
provenance and all capability/phase exits retain their independent requirements.
