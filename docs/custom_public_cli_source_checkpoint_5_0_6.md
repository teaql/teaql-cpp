## Confirmed comparator false acceptances

`compare_initialized_snapshot_cache_5_0_6.py` uses ordinary Python dictionary
equality in two ownership checks. Python treats Boolean values and the numbers
`0`/`1` as equal there. Two controlled executions of the actual CLI consequently
accept invalid JSON types:

- Native ownership vectors replaced with numeric `1` values.
- Original-source ownership vectors replaced with numeric `0`/`1` values.

The probe uses explicitly labeled output stubs derived from the retained corpus;
it does not claim to execute Rust or C++ runtime behavior. Positive profiles,
an incorrect ownership flag and a numeric substitution in stable common data
serve as controls.

An isolated copy changes only the two relevant equality conditions to use the
existing type-preserving `compare_values.same` helper. It accepts the valid
profiles and rejects both newly exposed numeric ownership substitutions. All
**10 original/candidate CLI runs** produce the expected exit codes. Path rewrites
used solely to run the isolated copy are recorded separately from the proposed
two-condition repair. No production, generator or worktree comparator code has
been changed by this experiment.
