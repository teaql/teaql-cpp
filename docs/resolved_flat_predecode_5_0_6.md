# Enhanced flat-graph predecode boundary (Rust 5.0.6)

## Source review finding

The locked `resolved.rs` noncompact flat-plan branch fetches enhanced rows,
creates a fresh root/builder, hydrates query and behavior plans, freezes the graph
and decodes the root models. It does not call `attach_flat_relation_graph` before
hydrating those flat plans. The embedded-graph fallback has a separate explicit
attachment step and must retain it.

C++ `EnhancedEntitiesOperation` additionally called the five-argument scoped-view
flattener before hydrating noncompact flat plans. That helper is a valid separate
composition protocol, but its unconditional use at this caller changes when row
payloads become graph relations and when nested model errors are evaluated.

## Direct reproduction

A byte-preserved original-runtime observer crosses continuous paging on/off,
child decoder registration on/off and absent/NULL/empty/successful/failing inline
child payloads. The query requests no relation load. One ready provider request
returns a parent row; handwritten carriers retain their incoming row and runtime
state, so observations distinguish payload preservation, relation views, identity
resolution and premature child decoding.

The [20 original results](parity/resolved_flat_predecode_original_5_0_6.json.gz)
all preserve inline payloads without creating an unrequested child view. The
[native pre-repair comparison](parity/resolved_flat_predecode_native_before_5_0_6.json.gz)
matches 16/20. All four differences require continuous paging and a registered
child decoder: NULL/empty rows acquire relation views, a populated child becomes
resolvable, and a failing child decoder rejects an otherwise successful root
query. Ordinary direct reads and absent decoder controls match.

This is an actual caller-level gap. Acceptance of either standalone graph
attachment protocol or relation hydration does not establish this composition.

## Rejected blanket removal

The candidate removes the extra scoped-view attachment from the noncompact
flat-plan branch while preserving query/behavior hydration, graph freeze and the
separate embedded fallback. The scoped-view helper itself remains available.
The candidate must also pass generated relation-analysis and matching/statistic
regressions before it can be accepted; the earlier C++ composition adaptation
must not be silently discarded merely because the new handwritten cases pass.

The [candidate regression receipt](parity/resolved_flat_predecode_candidate_regression_5_0_6.json.gz)
retains the complete failed run. Blanket removal matches the new 20/20 cases but
loses 12/2808 matching/statistic and 24/1944 relation-analysis results: generated
models no longer retain selected nested relations. It is not an acceptable fix.

## Explicit representation capability

`EntityDefaults::requires_flat_graph_hydration()` defaults to false. The enhanced
operation checks this optional compile-time capability before applying the C++
scoped-view adapter. Entities that do not inherit the defaults or expose the hook
also remain on the ordinary source-shaped path. The hook is runtime infrastructure,
not an application Q/E method; it does not grant query or mutation authority.

The generator's shared `generated_detail::Model` explicitly opts in because its
relation members are graph-backed. This keeps the existing generated graph
representation without forcing that representation on arbitrary `Entity` row
decoders. Dynamic-field support is a separate capability and is not used as a
proxy. Query preparation, plans, cursor publication, decoder registration,
Context ownership and the standalone attachment protocols remain unchanged.

Existing generated SDKs must be regenerated to carry the explicit opt-in. The
runtime-only default intentionally does not guess whether a type is generated.
The producer template is changed first; retained outputs are regenerated by the
normal generator command, never patched by hand. A generator unit assertion
requires the opt-in in the shared model output.

records the completed repair and preserves the earlier rejected candidate:

  [imported comparison](parity/resolved_flat_predecode_modules_repaired_5_0_6.json.gz)
  retain separate executable and input fingerprints.

  matching/statistic inputs match 2,808/2,808. All 36 blanket-removal regressions
  are restored without changing their inputs or expected outputs.

  retains 6,576 passing comparisons and **546 UNQUALIFIED review observations**;
  passing that command does not accept those unresolved source-failure cases.
- Focused ASan/UBSan passes 5/5: the new source comparison, NULL facets, repeated
  installation, reserved views and generated Context deletion/Global retention.
  Leak scanning remains disabled. These checks do not establish every asynchronous
  or graph lifetime path.
- Generator Java tests pass 79/79. The ordinary 25-workspace strict reproduction
  passes. The [complete active-SDK installation](parity/resolved_flat_predecode_sdk_install_5_0_6.json.gz)
  regenerates 80 SDKs, adds the same capability to 41 further SDKs, and verifies
  that every other generated byte is unchanged. Installed file hashes match the
  freshly generated outputs. Historical/source fixtures (2,467 protected files)
  retain their bytes. No generated file is patched by hand.
- The initial generator verifier detects stale specialized SDK fingerprints;
  after regeneration it passes all 42 locked generator sources and 17 capability
  records, with six capabilities still unqualified. Canonical module verification

  inventory, module paths and the locked baseline also pass.

The owned generation temporary directory is removed. Captured task logs occupy

Stable native (3.6 GiB), modules (2.6 GiB) and sanitizer (1.6 GiB) preset build
