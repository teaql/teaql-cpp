# Standalone generated registries and SQL schema provider

Status: standalone registry/schema surfaces are implemented and representative
original/native/imported/lifetime/compiler gates pass. Broader G12 model/runtime
configuration/customization, sample/Assist and final integration remain open. This is G12/P6 work; full P0-P7 scope remains active.

The locked runtime template exposes repository, behavior and checker factories
independently of its four RuntimeModule factories, a separate LocalSchemaProvider,
and data-service aliases. Prior C++ generation supplied module registration and
metadata lookup but omitted those public surfaces. Existing runtime registries
provide their allocation, lookup, replacement and checked-resource mechanics;
the generator must emit model registrations rather than duplicate those methods.

The new GeneratedLocalSchemaProvider uses a stateless model dispatch callback.
Each successful lookup allocates a fresh EntityDescriptor in the provider's
explicit domain. Unknown names return null. Explicit provider/descriptor Global
copies survive User deletion; User refs expire. The shared-kernel native,
imported and selected sanitizer fixture passes with null default PMR. The helper
uses the data-service SchemaProvider SPI and remains distinct from runtime
schema initialization and mutable Context metadata. A shared binding overload
accepts that distinct provider; its native separation check is pending.

The unchanged original Business-ID library supplies actual standalone factories.
Thirteen [original observations](parity/generated_registry_schema_original_5_0_6.json)
cover all modeled names, case/unknown/empty/embedded-NUL names, complete repository
Debug, independent clone extension, Behavior lookup/default execution, Checker
names and Tenant findings for valid/blank/long/Unicode inputs, and complete schema
Debug, fresh identity and clone equality. Default replacement in registry clones
retains another model's registrations. No original generated file or old observer
lock is changed. The observer's initial import/location mistakes are retained;
the final source compiler exits before execution.

Next gates require thin generated aliases, named schema dispatch and independent
registry factories; actual comparison of all recorded outcomes; custom registry
replacement/ownership behavior; real SQL binding independent of Context metadata;
accurate Assist; strict artifact reproduction and relevant compiler/native/module/
lifetime selections. A named function or matching inventory cannot close this
responsibility or the remaining assembly qualification matrix.
