## Ownership and harness corrections

Native tests disable default PMR allocation. Models, custom logic, hooks, metadata,
checker registrations and policy state allocate in the UserContext. The result
is explicitly copied into Global; all stack PMR inputs/results leave scope before
actual User deletion, then the Global-owned result is serialized. Registry
callbacks capture the allocator pointer by value and borrow their managed policy.
No shared owner extends the closed User lifetime.

Initial test compilation exposed a missing direct SQLite-provider dependency in
the new Rust manifest and two native optional-string call sites using Value where
the generated API requires an optional String. The manifest and test calls were
corrected; no generated or runtime API changed. The first comparison also used
six availability fields in Rust and eleven in C++. Its
[initial differences](parity/inherited_checker_helpers_5_0_6_initial_gaps.json.gz)
are retained. Both observers now expose the same eleven actual availability
queries. This is a harness projection correction, not output normalization or a
change to original load-state algorithms.

## Reproduce

```sh
set -e
source scripts/toolchains/activate.sh
cmake --build --preset native --target \
  teaql_inherited_checker_helpers_document_probe \
  teaql_inherited_checker_helpers_intermediate_record_probe \
  teaql_inherited_checker_helpers_invoice_probe \
  teaql_inherited_checker_helpers_receipt_probe \
  teaql_inherited_checker_helpers_special_invoice_probe teaql_sample_fixed_clock
python3 scripts/verify_inherited_checker_helpers_5_0_6.py
ctest --preset native --output-on-failure \
  -R '^inherited_checker_helpers_.*_rust_parity$'
```

Module tests use the same expression with `module_` prefixed. The clock-controlled
tests are registered only on native Linux, matching the existing clock fixture.
