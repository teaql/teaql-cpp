# Business consumers of compiler-generated SDKs

The [evaluation/controller checkpoint](generator_evaluation_alignment_5_0_6.md)
qualifies ordinary query and governed graph Save through the configured compiler
route. This continuation exercises the dedicated expression/JSON and generated
Checker/Fix consumers against freshly generated complete libraries.

1. Compile independent locked-reference and current Java classpaths. Install the
   existing full model-configuration compiler capability through trusted source
   service assembly and invoke the actual upload controller, including evaluation.
2. Preserve the three original reverse-relation model refusals. Derive positive
   controller fixtures by adding the required `child._audit_mask_fields="secret"`
   declaration, with original XML and the exact edit retained. Keep concrete
   Self, child to-one and child to-many projections unchanged. Compile both
   complete generated libraries with the retained query/E/JSON consumers. Compare

3. Generate the original Tenant/Note Checker model through the same route.
   Compile the unchanged Rust consumer against the newly generated library.
   Redirect only the C++ consumer's generated-header include to the new SDK;
   preserve every function body. Re-execute all retained direct/preflight and
   actual SQLite commit cases, including custom Fix, Context/clock evidence,
   Policy, rejection, trigger rollback and optimistic conflict.
4. Bind raw process inputs/outputs, generated SDK manifests, the original
   library, compiler descriptors/MIR, dependency lock and toolchain. Verify
   successful receipt admission and corruption rejection under ordinary and
   optimized Python, including imported validation helpers.
5. Retain compact evidence and failures, remove owned disposable outputs, update
   the capability ledger without promoting incomplete responsibilities, and
   publish the coherent checkpoint.

Existing runtime functions, generated API contracts, Context lifetimes and
provider boundaries remain authoritative. No runtime dependency is added.
The existing probes deliberately project clock changes and common-operation
clock equality rather than nondeterministic timestamps; their original
projection is unchanged. Fresh execution and retained expected observations
are separate checks. This finite consumer matrix does not complete all Rust
configuration/type/storage mappings, the remaining identity decisions, or the
G13/G14/G17 and complete P0-P7 exits.

## Initial evaluation diagnosis

The first invocation retains a launcher error: the existing linker capability
is an object containing a path and fingerprint, not an environment string.
The next actual controller attempt reaches evaluation and refuses the old
reverse-relation fixture before compiler dispatch. Independent fresh locked
and current evaluation classpaths identify the same `KSML-PRIVACY-001-ERR`:
`child.secret` is a credential field without an audit mask. All three original
relation fixtures refuse for this reason; the unchanged Checker fixture has
no evaluation errors. Their complete findings and original models remain in
the separate diagnosis receipt. The positive fixture adds the requested mask
on both sides, rather than bypassing controller evaluation. It preserves the
relation types, column names, actual business reads and original observer bodies.
