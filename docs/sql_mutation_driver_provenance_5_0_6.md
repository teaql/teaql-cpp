## Shared provenance tooling

The [archive driver tool](../scripts/archive_driver_provenance_5_0_6.py) provides
development replay and build-free routine validation for an explicit project
registry. It retains actual Cargo metadata, targets, complete dependency locks,
input-helper identities and raw stdin/stdout/stderr. Source compilation uses
`--offline --locked --bins`; every registry dependency must belong to the exact
reference lock. All local dependencies must be the explicit owned project or
the declared TeaQL archive packages.

Replay uses one owned temporary directory for source, targets and child scratch
files. The original collector manifests, source files, generated artifacts and
shared caches remain untouched. Preparation resolves only the new source lock,
then verifies it with locked metadata before compilation. Source replay and
verification do not add dependencies to the C++ runtime.

## Scope boundaries

The declared-driver worklist is one provenance category. Completing its last
three entries does not establish complete SQ02: other direct registrations,
custom CLI/dependency/normalization obligations, metadata grammar/configuration
and protected execution retain independent requirements. Original Rust unit-test
execution, fresh full native integration, imported execution, sanitizer/MIPS,
external integrations and physical-device execution are not established by a
source build or archive hash.
